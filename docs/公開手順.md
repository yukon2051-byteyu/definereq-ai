# Hugging Face Spaces 公開手順

2026-11-05 に本人の確認を得て `yukon2051/definereq-ai` へ公開しました（public）。Secrets は本人が登録済みで、有料機能も動作を確認しました。

## 確認した公式仕様（2026-11-05）

| 項目 | 内容 |
|---|---|
| 作成条件 | Docker Space の作成には有料プラン（PRO $9/月）が必要 |
| 無料CPU | CPU Basic：2 vCPU・16GB・ディスク50GB（永続ではない） |
| 休止 | 48時間使われないと休止。誰かが開くと再起動する |
| ディスク | 再起動・停止で消える |
| 永続保存 | Storage Bucket をマウント可能。本アプリは使わない |
| ポート | `app_port` で指定（本アプリは8501） |
| 実行ユーザー | UID 1000 |
| 外部通信 | 80・443・8080番のみ。**5432番は使えない** |
| Secrets | Settings で登録し、実行時に環境変数として渡される |
| 公開範囲 | public はソースコードも公開される。protected はPROでコード非公開、アプリは公開 |

### 外部通信の制限と利用記録（重要）

公式文書では、外部へ通信できるのは80・443・8080番です。PostgreSQL の標準5432番はこの範囲外のため、外部DBへ接続できない可能性があります。そのため利用記録は **Hugging Face の非公開データセット**（443番）を第一候補とし、外部の PostgreSQL は代替にしています。無料CPUは1台で動く（複製は有料機能）ため、プロセス内のロックで予約を排他制御できます。複製を使う場合はこの方式を使えません。

## 手順

### 1. 事前準備

1. PROの契約状況を確認する（有料。本人の判断）
2. 利用記録用の**非公開**データセットを作成し（例：`ユーザー名/definereq-usage`）、そのデータセットへ書き込めるトークンを用意する
3. Claude Console と OpenAI の管理画面で月額上限を設定する

### 2. 送るファイルの確認

```powershell
.venv\Scripts\python scripts\deploy_hf.py ユーザー名/definereq-ai
```

一覧が表示されるだけで、何も送信しません。`tests`、`scripts`、`.env`、指示書は送りません。README から参照する `docs` は送ります。

### 3. 反映

```powershell
# ログイン済みなら次の1行は不要
$env:HF_TOKEN = "（書き込み権限のトークン）"
.venv\Scripts\python scripts\deploy_hf.py ユーザー名/definereq-ai --yes
```

public の場合、送ったコードとデモ資料は誰でも閲覧できます。実案件のデータ、秘密情報、許可のない録画は含めないでください。

### 4. Secrets と Variables の登録

Settings で [.env.example](../.env.example) の項目を登録します。

| 種類 | 名前 | 必須 |
|---|---|---|
| Secret | `ANTHROPIC_API_KEY` | AIを使う場合 |
| Secret | `OPENAI_API_KEY` | 外部APIで文字起こしする場合 |
| Secret | `HF_TOKEN` | 有料処理を使う場合（利用記録の保存） |
| Variable | `USAGE_HF_DATASET` | 有料処理を使う場合 |
| Secret | `USAGE_DATABASE_URL` | データセットの代わりに外部DBを使う場合のみ |
| Secret | `DEFINEREQ_ACCESS_CODES` | 有料処理を使う場合 |
| Variable | `DEFINEREQ_MONTHLY_API_BUDGET_JPY` など | 任意 |

Secrets が未設定でもトップページとデモは動きます。

### 5. 公開後の確認

[テスト結果](テスト結果.md) の「未検証」の項目を確認します。

- 独立URL（`https://ユーザー名-definereq-ai.hf.space`）でのトップ、デモ、Word・Excel・JSON出力
- PCとスマートフォンでの表示
- 録画ファイルのアップロード
- 休止からの復帰の時間
- 2つのブラウザで操作して、データが混ざらないこと

## 再起動・休止で起きること

| データ | 扱い |
|---|---|
| 案件 | ブラウザの接続中のみ保持。再起動で消えるため、**JSONで保存して再開する** |
| 利用記録 | 非公開データセット。再起動でも残る |
| アップロードの一時ファイル | 再起動で消える。6時間で削除対象 |

## 制約

- アプリが起動する前のホスティング側の待ち時間は、アプリの表示では解消できません
- 休止中は開いてから起動まで時間がかかります（手動の再起動は15秒でした。48時間の休止からの復帰は未計測）
- 無料CPUでは同時に重い処理を行うと遅くなります
- 長時間の処理中に接続が切れると、その処理の結果は失われます。文字起こしは区間を分けて実行してください
- バックグラウンド処理は使っていないため、再起動時に再開する処理はありません

## 起動の仕組み

Dockerfile は `python:3.12-slim` を使い、UID 1000 で動かします。動画処理の PyAV は ffmpeg を内蔵するため OS の追加導入は不要です。日本語はブラウザ側のフォントで表示し、Word・Excelは閲覧する端末のフォントを使うため、サーバーに日本語フォントは不要です。

ビルド時に有料APIは呼びません。起動時にモデルのダウンロードもしません。
