# データ構造

案件は1つのJSON形式のデータです（`format_version: 1`）。定義は `definereq/schema.py` にあります。

## 全体

| 項目 | 内容 |
|---|---|
| `app`, `format_version` | 形式の識別 |
| `id`, `name`, `domains`, `traits` | 案件の基本 |
| `profile` | 案件情報。各項目は `{value, certainty}` |
| `prep` | 現時点の理解、不足情報、議題など |
| `nfr_status` | 非機能の確認状況 |
| `is_demo`, `demo` | デモの情報 |
| `activity` | 操作の記録 |
| `seq` | ID採番の管理 |

## 一覧

| 一覧 | ID | 内容 |
|---|---|---|
| `meetings` | MTG | 会議（ID・会議名・開催日）。資料・録画・質問・判断・追加要望・履歴が `meeting_id` で参照 |
| `stakeholders` | STK | 関係者 |
| `glossary` | TRM | 用語 |
| `sources` | SRC | 資料（版、位置付きの単位、警告、補足） |
| `recordings` | REC | 録画と発言区間 |
| `questions` | QST | 質問と回答 |
| `candidates` | CAN | AI候補と採否 |
| `requirements` | REQ | 要件（`versions` に旧版を保持） |
| `issues` | ISU | 意見調整 |
| `scenarios` | SCN | シナリオ |
| `decisions` | DEC | 判断と合意（`confirmation` に確認の記録） |
| `changes` | CHG | 追加要望と影響 |
| `conflicts` | CNF | 矛盾候補（検出時の版と文章を `detected` に保持） |
| `risks` | RSK | リスク |

| `history` | HIS | 仕様の変遷（追記のみ） |
| `baselines` | BSL | 基準版 |
| `shared_docs` | DOC | 発行した共有資料 |
| `responses` | RES | 回答 |
| `ai_runs` | AIR | AI結果の記録（入力の指紋で古さを判定） |

## 要点

**未設定と該当なし：** `None` は未設定、`"__該当なし__"` は該当なしです。

**根拠：**

```json
{"source_id": "SRC-001", "unit_id": "U0003", "version": 1, "quote": "引用", "locator": "p.3", "verified": true}
```

**数値条件：**

```json
{"metric": "目標復旧時間（RTO）", "value": 4, "unit": "時間以内", "kind": "必要条件", "origin": "関係者が提示",
 "condition": "基盤障害時", "basis": "第2回打ち合わせ", "status": "確認待ち"}
```

`verify` は達成の検証の記録です（例：復旧試験：未実施）。要求値の合意は判断の記録から求めるため、保存しません。`origin`（出所）は 関係者が提示／資料に記載／AIの確認用候補／未確認 のいずれかです。誰が示した値かを表し、`status`（確認が済んだか）とは別に持ちます。古いJSONにはないため、その場合は「未設定」と表示します。

**判断の対象の版：**

```json
{"id": "DEC-001", "state": "合意済み", "related_requirements": ["REQ-001"], "target_versions": {"REQ-001": 1}}
```

合意済みにした時点の要件の版を記録します。要件の版が変わると、その判断は人が確認し直すまで反映できません。記録がない古い判断は、版を判定できないものとして扱います。

**候補の追跡：** 候補から作った要件・質問・行動などには `from_candidate`、候補には `resolved_items`（反映先のID）を残します。`questions` の `category` は「質問」または「確認事項」です（項目がない古いデータは質問として扱います）。候補の状態に「要再確認」を追加しました。

**案件情報：** `profile` に `users`（利用者）を追加し、各項目に任意で `origin`（出所）を持ちます。古いJSONは読込時に補います。形式の版は2のままです。

**状況案内（任意の項目）：**

```json
{"guidance": {"user_stage": "before_first",
 "notes": [{"state_fp": "状態の指紋", "advice_id": "prep", "advice_title": "初回会議の準備", "generated_at": "2026-11-06T10:00:00",
            "model": "claude-opus-5-5", "items": [{"kind": "確認する質問", "text": "…"}], "cost_jpy": 3.2}]}}
```

形式の版は2のままです。項目がない古いJSONも読み込めます。この項目が壊れている場合は、案件の読込を止めずに該当部分だけを捨てます。要件や判断の記録には影響しません。デモの表示状態と体験済みの表示はJSONに保存しません。

`kind` は 必要条件／現状の計測値／仮定・見積もり／実現方式の候補／人が確定した設計制約 のいずれかです。

**履歴：** `meeting_date`、`proposed_on`、`decided_on`、`applied_on`、`recorded_at` を分けます。不明な日付は `null` のままです。訂正は `corrects` で元の履歴を指す新しい行を追加します。

**読込の検証：** 形式版、必須項目、一覧の有無、重複ID、ID形式、状態の値、要件間の参照、根拠の資料、会議の参照を確認します。合格したときだけ案件を差し替えます。

**形式の版：** 現在は版2です。版1のファイルは読込時に変換します。録画と議事録から会議を作り、判断と履歴を根拠の資料が属する会議へ関連付けます。開催日の記録がない場合は日付を補いません。版2より新しいファイルは理由と対処を示して拒否します。

**含まないもの：** 元の動画・資料ファイル、APIキー、AIパスワード。

元ファイルのバイナリは含みません。録画は名称、時刻、文字起こしのみです。

他作品との連携に備え、要件IDはJSON・Excelに出力しています（直接連携は未実装）。
