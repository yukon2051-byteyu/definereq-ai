# デモ説明

3件とも架空のデータです。AIの結果は事前に用意したもので、有料APIは使いません。

サンプル資料は実際に読み込み、本番と同じロジック（根拠の照合、合意、反映、履歴）で案件を構築しています。

## 共通の体験

| 項目 | 内容 |
|---|---|
| 3分の案内 | 背景→工程→まとめの8画面。各画面は「見出し→ここに注目→分かること・残る確認事項→原文→前後の移動」の順。代表例だけを表示し、抜粋であることを件数で示す |
| 全画面の閲覧 | 「関連する全件を見る」「案内を閉じる」から移動し、一覧・根拠・履歴を自由に見る。「案内へ戻る」で元の工程に戻る |
| 段階 | 会議前、会議後、変更、判断後を切り替え |
| 閲覧専用 | デモでは編集できない。入力欄は無効で、保存や編集のボタンは表示しない |
| 出力 | Word・Excel・JSONは出力できる。デモでは発行の記録を増やさない |
| なぜこの仕様か | 質問は入力でき、登録情報から回答する |

約3分は想定時間です。実測はしていません。

## デモ1：申請・承認アプリの刷新（業務アプリ）

| 段階 | 内容 | 確認できること |
|---|---|---|
| 会議前 | 要望メモ（TXT）、規程（PDF）。質問を準備 | 「承認後は変更不可」の範囲の確認 |
| 会議後 | 議事録（Word）、第2回字幕（VTT）。佐藤と田中の対立、3案の比較 | 再申請を採用。話者が未確認の発言は根拠にせず、判断は確認メールで記録。AIの推測「上限5回」を数値の創作として却下 |
| 変更 | 経理の直接訂正の要望、領収書添付 | 受付だけでは要件が変わらない。矛盾候補、影響、未調査の領域 |
| 判断後 | 直接訂正を却下し、経理の代行作成を採用 | 変更前後、却下の理由、保留、再確認の対象 |

期待結果：「なぜ再申請なのか」に、監査で説明できることを理由として、比較した案、判断者、引用を回答する。

## デモ2：拠点売上集計の自動化とクラウド移行（業務アプリ＋インフラ）

| 段階 | 内容 | 確認できること |
|---|---|---|
| 会議前 | 移行計画案（PowerPoint）、処理量（Excel）、運用メモ | ノートは対象外。図は未理解と表示し、人が補足。増加率は未計測 |
| 会議後 | 議事録、貼り付けメモ | 「毎朝すぐ」→8時30分。「失いたくない」→RPO 1日分。RTO・RPO・計画停止を分離。未提出・重複・遅延のシナリオ |
| 変更 | 締め後の再集計の要望 | 締め後固定との矛盾候補 |
| 判断後 | 訂正版を翌営業日までに作成 | アプリと基盤を分けた要件定義書 |

期待結果：「なぜ復旧は4時間以内なのか」に理由を回答する。「なぜ保存期間は3年なのか」には「理由の記録がありません」と回答する。

## デモ3：拠点ネットワーク更新と遠隔保守（ネットワーク）

| 段階 | 内容 | 確認できること |
|---|---|---|
| 会議前 | 通信一覧（Excel）、構成説明（PowerPoint）、規程抜粋 | ポートは未確認のまま。線のつながりは人が補足 |
| 会議後 | 架空の音声付き録画（MP4）と準備済みの文字起こし | 時刻付きの根拠と再生。通信量・切替時間は未計測。保守担当の提案は確認待ちのまま |
| 変更 | 常時接続の要望 | 分離、運用への影響。責任分界は未調査 |
| 判断後 | 今回は現地対応、時間限定の接続は次回 | 判断者はセキュリティ責任者。残る矛盾候補は未確認のまま |

期待結果：「なぜ遠隔保守を今回やらないのか」に、規程の例外の条件がそろっていないことを、引用とともに回答する。機器・速度・設定の十分性は保証しない。

録画は Windows の音声合成で作った架空の音声です。実物の faster-whisper で文字起こしできることを確認しましたが、デモの画面では誤認識を含まない準備済みの文字起こしを使っています。

## 見せ方（面接）

1. デモ1の案内で「発言が要件になるまで」を見せる
2. 「なぜ再申請なのか」と「なぜ部長の承認が必要なのか」で、理由が別々に返ることを見せる
3. デモ2で「理由の記録がありません」を見せ、AIが埋めないことを説明する
4. デモ3で提案が合意にならないことを見せる
