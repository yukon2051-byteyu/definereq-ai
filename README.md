# DefineReq_AI

**AI要件定義・変更経緯管理システム**

あなたの要件定義に、伴走するAIを

事前情報からヒアリングを準備し、Web会議の録画や議事録から要望・決定・未決事項を整理します。業務アプリ、インフラ、ネットワークの要件について、見落とし、仕様の矛盾、追加要望の影響を確認し、関係者との認識合わせ、要件定義書の作成、仕様変更の経緯の追跡まで支援します。

> **公開デモ：https://yukon2051-definereq-ai.hf.space** （登録不要・料金なし。48時間使われないと休止し、開いたときに自動で起動します）
>
> 個人開発のポートフォリオです。デモのデータは全て架空です。要件定義の完全性や正しさを保証するものではなく、人が確認・判断するための根拠と残件を示します。

## 解決する業務課題

- 議事録に「決まったこと」と「言っただけのこと」が混ざり、後から合意の有無が分からない
- 「速く」「止めないで」のような要望が、測定できる条件にならないまま進む
- 追加要望を受けたとき、影響範囲と過去の判断との矛盾を調べるのに時間がかかる
- 半年後に「なぜこの仕様なのか」を聞かれても、理由と比較した案が見つからない

## 対象

社内SE、ITコンサルタント、要件定義を担当するSE・PM、インフラ・ネットワークの企画導入担当者、顧客や利用部門との調整担当者。業種は限定しません。

| 既存作品 | 役割 |
|---|---|
| AI-BIC | 何を改善するかを整理する |
| ChangeScope AI | 組織・業務・システム間への変更の波及を整理する |
| ReadyProof AI | 製品が要件に合うか、実際に満たしたかを確認する |
| **DefineReq_AI** | **何を実現するかを関係者と決め、要件の整合性と決定経緯を管理する** |

## 3件の無料デモ

APIキーや登録なしで見られます。デモは閲覧専用です。AIの結果は事前に用意したもの（準備済み）で、料金は発生しません。

| デモ | 分野 | このデモで分かること | 見どころ（近道で直接開ける画面） |
|---|---|---|---|
| 1 経費申請アプリの刷新 | 業務アプリ | 対立する要望から、判断と変更を追う | 直接変更・再承認・再申請の3案の比較と、再申請を採用した理由・根拠 |
| 2 拠点売上集計の自動化とクラウド移行 | 業務アプリ＋インフラ | 曖昧な要望を、測れる要件にする | 「毎朝すぐ」「失いたくない」を、完了時刻・復旧時間・許容データ損失に分ける場面 |
| 3 拠点ネットワーク更新と遠隔保守 | ネットワーク | 録画の発言から、合意の根拠を確認する | 架空の音声付き録画で、保守会社の発言が「提案」であり決定ではないことを確かめる場面 |

各デモは8つのステップで見られます。

- **冒頭：** 立場の異なる2つの主張（例：現場の要望と経理の制約）と、今回の論点を最初に示します。順に進む操作と、見どころへの近道の両方を用意しています。
- **現在地：** 本文の上部に、大きな区分（例：背景と準備 → 比較と判断 → 変更と成果物）とステップ番号を表示します。
- **判断の画面：** 採用した案 → 採用理由 → 根拠 → 案の比較 の順に示します。根拠は「本人確認済みの記録」「話者確認済みの発言」「判断に使っていない発言（話者未確認）」に分けて表示します。
- **判断後の仕様：** 比較表より先に、変更前・変更後・引き続き守る制約と、「追加要望 → 過去の判断との衝突 → 採用した対応」を示します。
- **詳細画面：** 実際の一覧や記録を開けます。戻るボタンは「← 5. 訂正方法の比較に戻る」のように、開いた元のステップを示します。
- **終了画面：** 体験の終了と、案件に残る未確認の項目を分けて示し、サンプル資料（Word・Excel）を確認・ダウンロードできます。

画面に出す発言・判断・数値・変更前後の文は、その時点の案件データから取得し、記録と照合しています。記録にない文を書くとテストで検出されます。

機能対応表は [docs/デモ説明.md](docs/デモ説明.md) を参照してください。

## 主要機能

| 領域 | できること |
|---|---|
| 分野の切替 | 業務アプリ・インフラ・ネットワーク・複合で質問と文書の章立てが変わる。複合では重複をまとめる |
| 会議前の準備 | 現時点の理解、不足情報、議題、質問と優先順位、確認相手 |
| 資料・録画 | PDF / Word / Excel / PowerPoint / テキスト / SRT / VTT、MP4 / WebM / MOV の文字起こし |
| 根拠 | 引用が原文に実在するかをプログラムで照合。位置（ページ、セル、スライド、時刻）を保持 |
| 整理 | 候補の採否、要件の版管理、具体化と受入条件、非機能、範囲、シナリオ |
| 調整・合意 | 意見の違いの整理、選択肢の比較、合意の記録（人の操作のみ） |
| 変更 | 追加要望の受付、影響調査（未調査の領域も表示）、矛盾候補の検出 |
| 経緯 | 仕様の変遷、「なぜこの仕様か」への回答、基準版との比較、再確認の対象の検出 |
| 出力 | 打ち合わせ確認資料・追加要望確認資料・要件定義書（Word）、Excel、JSON |
| 継続利用 | 案件JSONから再開し、複数回の会議を同じ案件の続きとして記録。未決事項と宿題を次回へ引き継ぐ |
| 状況案内 | 案件データから現在の状況・次にすること・案内の理由をプログラムで判定して表示。必要なときだけ、ボタン操作でAIの補足を追加 |
| 案件の準備 | 新規案件は「案件の準備」から始める。背景・目的・関係者と、資料・議事録のどちらからでも始められ、状態（未入力・入力済み・未保存の変更あり、取り込み済み N件）を表示 |
| 次にすること | 案件の状態から、次の作業（会議の記録を整理する／要件候補を確認する／会議の準備へ進む）を主ボタン1つで示す。資料の登録直後にも表示 |
| 入力途中の保持 | 保存前に別の画面へ移っても、入力途中の内容（下書き）を案件ごとに保持する |
| 議事録の取り込み | 「議事録を取り込む」と「その他の資料を取り込む」を最初に選ぶ。登録する種類をボタンの近くに表示 |
| 候補の反映 | AI候補の種類に合う場所（質問、議題、確認事項、宿題、要件、リスク、判断の下書き）へ人の操作で反映。要件へは分類候補と分割案を確認して採用 |
| 合意の反映 | 合意済みの判断を、人が選んだ要件へ反映。判断した版と異なる要件には反映しない |
| 出力前確認 | 要件定義書の作成前に、合意・未合意・分類未設定・受入条件未設定・未処理候補の件数と、未決事項の登録・掲載・除外の件数を実データで表示 |
| 未決事項の掲載 | 確認事項、要件の未確認事項、保留、依頼などを1つの一覧にまとめて文書へ掲載。同じ内容は関連を保って統合し、除外は理由を表示 |

## AI・プログラム・人の役割

| 担当 | 役割 |
|---|---|
| AI | 質問・論点・要件・リスクの候補作成、資料の整理、状況案内の補足（内容の解釈が必要な部分） |
| プログラム | ID・版・履歴の管理、引用の照合、集計、古い結果の検出、費用の制限、状況案内の判定 |
| 人 | 条件の確定、発言と話者の確認、優先順位と範囲の判断、合意と変更承認の記録 |

AIの出力だけで要件や合意は確定しません。AIには外部操作の権限を与えていません。「なぜこの仕様か」は登録済みの情報からプログラムが組み立てるため、AIの料金はかかりません。

## 要件と詳細設計の境界

必要条件・現状の計測値・仮定と見積もり・実現方式の候補・人が確定した設計制約を区別して記録します。人数だけで機器や帯域を断定せず、不明なポートやプロトコルを作りません。機器設定の投入、ネットワーク探索、外部システムの操作は対象外です。

## 対応形式と制限

| 項目 | 内容 |
|---|---|
| 資料 | 1ファイル20MBまで。Office は本文のみ読み、マクロは実行しない。パスワード付きPDF・旧形式は不可 |
| PowerPoint | スライド・表・グループ内の文字を抽出。発表者ノートは初期状態で対象外。画像・矢印・グラフは未理解と表示 |
| 録画 | 200MBまで。1回の文字起こしは30分まで（長い録画は区間指定）。映像の理解とOCRは非対応 |
| PDF出力 | 非対応。Wordで開いてPDF保存してください |
| デモ | 閲覧専用。編集は「あなたの案件で試す」から行う |
| 案件の保持 | 画面の利用中のみ。JSONで保存し、トップから再開する。元の動画・資料ファイルはJSONに含まれない |
| スマートフォン | トップページ・デモ選択・閲覧を想定。表の編集はPCを推奨。2026-11-09 のデモの改修はデスクトップ表示を対象に確認 |

## 使用技術と選定理由

| 技術 | 用途 | 理由 |
|---|---|---|
| Python 3.12 / Streamlit | 画面 | 初学者でも保守しやすく、既存作品と共通 |
| Claude API | 候補の作成 | JSONスキーマで出力を固定できる |
| OpenAI 文字起こしAPI / faster-whisper | 文字起こし | 話者ラベル付きAPIと、無料のローカル処理を切替可能 |
| PyAV | 動画の検証・音声の取り出し | ffmpegを内蔵し、外部コマンドを実行しない |
| python-docx / openpyxl | 出力 | Word・Excelを直接生成 |
| Hugging Face データセット / PostgreSQL | 利用記録 | 再起動で消えない。Spaces の通信制限に収まるデータセットを第一候補にした |
| Docker / Hugging Face Spaces | 公開 | 無料CPUで実行できる |

## 使い方

```powershell
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\streamlit run app.py
```

環境変数は [.env.example](.env.example) を参照してください。全て未設定でもトップページとデモは動きます。

Docker の場合：

```bash
docker build -t definereq-ai .
docker run -p 8501:8501 definereq-ai
```

公開手順は [docs/公開手順.md](docs/公開手順.md)、費用は [docs/費用計画.md](docs/費用計画.md) を参照してください。

## テスト

```powershell
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest tests
```

自動テストは代替応答を使い、実APIを呼びません。2026-11-09 時点で492件です。

画面の動きは、実際のブラウザ（Edge）を操作するスクリプトでも確認しています。いずれも架空の案件を使い、AIは呼びません。

| スクリプト | 確認すること |
|---|---|
| `scripts/guide_check.py` | 3件のデモの全ステップ（PC幅・スマートフォン幅）、資料のダウンロード、録画の再生 |
| `scripts/demo_flow_check.py` | デモの一覧・冒頭・見どころ・判断・判断後の仕様・終了画面（デスクトップ） |
| `scripts/setup_flow_check.py` | 案件の準備、背景と資料の往復、下書きの保持、トップの入口 |
| `scripts/source_flow_check.py` | 背景・資料の画面の配置、議事録の種類、1回の操作での保存と移動、再開用ファイル |
| `scripts/next_flow_check.py` | 案件の準備と資料の登録直後の「次にすること」 |
| `scripts/project_flow_check.py` | 実案件の一連の流れ（AIの応答だけ代替応答に差し替え） |

実行結果と未検証の項目は [docs/テスト結果.md](docs/テスト結果.md) に記録しています。
